# ADR 0001 · 产品定位：高质量的个人产品

- 日期：2026-11-11
- 状态：已确认（项目所有者决策）
- 影响范围：全部后续迭代的取舍判据

## 背景

项目自 2026-08-27 裁剪为「个人本地版」：移除数据库、账号/鉴权、社区/分享、评分、跨模型对比、教程页、Remix、发布链路及 SSRF/限流/Sentry 等防护层。此后围绕「这个项目值不值得继续投入、还差什么」反复评估。为避免在「工具 / 作品 / 产品」之间摇摆，明确一次定位，作为后续所有功能取舍的唯一判据。

## 决策

定位为**高质量的个人产品**：只服务本人、按产品级标准打磨，不追求用户量、不做增长、不做商业验证。

两个词各自是硬约束：

- **个人** → 明确不做：账号体系、多用户、社区/分享、公网部署、跨设备同步。数据只在本机，Key 只存本地。上一轮路线中的 P2 全部冻结。这也意味着 `/relay` 作为开放代理的风险边界必须收紧（本机自用不等于可以不设防）。
- **产品** → 明确拒绝「能跑就行」：每个留下来的功能必须闭环、可判定、可追溯、有失败兜底。

因此本项目的「高质量」是**减法而非加法**：不是堆功能，是把已有链路磨到没有毛刺。新增功能前先问「是否让某条已有链路更完整」，否则不做。

## 已主动裁剪且不再回补的能力

数据库与账号、社区/分享/审核、评分体系、跨模型对比、教程页、Remix、本地/公网发布。这些是 8-27 的主动决策，不是技术债，不要以「补完整」为由回补。

## 「高质量」的可判定基线

| # | 基线 | 判定方式 |
|---|---|---|
| 1 | 链路闭环 | 每个入口功能都有「结果 → 可查看 → 可回退/重试」的完整路径，不留半截流程 |
| 2 | 数据可信 | 口径自洽、分母明确、噪声可见；看板数字能解释得清，不让用户误判流程故障 |
| 3 | 可观测 | 关键链路有 token/成本/耗时记录，且 LangSmith 关闭态零开销、零网络 |
| 4 | 失败可解释 | 任何错误给出可操作的原因与下一步（关键反例：设置页「使用代理」开启但后端未启动时只抛 `network error`） |
| 5 | 隐私边界清晰 | Key 不出本机、上报只含脱敏摘要、CSP 白名单可枚举 |
| 6 | 结论可复现 | 评测类结论有可重跑的脚本与固定基准集，不是一次性口述数据 |
| 7 | 决策可追溯 | 架构取舍有 ADR，实质改动同步 README，改动有离线回归测试兜底 |

## 收敛后的迭代路线

### P0 · 质量地基（先做完，不进入 P1）

1. **补 ADR 与决策基线**：本文件即为起点；后续每个方向性决策追加一条 ADR。
2. **`/relay` 最小白名单**：当前是开放直连代理（无 SSRF 校验、无 Key 校验），是唯一真实安全硬伤。加最小域名白名单即可，不引入完整防护层。
3. **失败可解释收口**：把 `network error` 一类无信息量错误，替换成「代理开关 + 后端连通性」的具体提示。
4. **看板两项待定收口**：failover 的 `·attempt` 记录是否计入「调用次数」；「已过滤 N 条探针」提示条上移。

### P1 · 方法论深化（差异化最高）

1. **模板回归评测**：打通「版本历史 + 6 维裁判 + 33 场景基准集」——改了骨架自动跑基准集，看分数是否退化。这是唯一补上产品逻辑缺环的迭代，让项目从「能生成」变成「能演进」。
2. **结论产物化**：benchmark 跑成可复现脚本 + 报告（`scripts/` 已有 6 个 mjs），同时是技术文章素材。
3. **多裁判一致性**：跨厂商已做（deepseek 判 qwen），再加一个裁判算评分方差/一致率，回答「裁判本身可信吗」。

### P2 · 冻结

轻量持久化、分享与导出、公网部署。这些会推翻「个人本地版」边界，属于定位变更而非技术升级；若将来要做，先开新 ADR 重新决策，不走「顺手加上」的路径。

## 验收原则

不以「代码写完」为完成，以基线表中对应条目「可判定通过」为完成。每次实质改动同步 README.md。

## 已知边界

- 个人本地工具，无真实用户与留存数据；其价值定位为「能力资产 + 方法论资产」，不包装为产品/商业成功。
- `:8000` 不得公网暴露（Key 明文存 localStorage、`/relay` 为开放代理）。P0-2 完成后此约束可放宽但仍不建议公网暴露。
